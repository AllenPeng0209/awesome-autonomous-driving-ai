## 为什么选

它没有将“未来预测更准”直接当成规划价值，而是分别控制辅助监督、未来注入与几何注意力。尤其值得研究的是梯度分工：允许动作目标塑造共享表征，又避免动作损失直接改写预测器。这为已有 scene token 模型提供了可检验的融合方式，而不是要求所有 token 变成固定空间网格。

## 方法与关键结果

当前前视图经 DINOv3 编码，JEPA 预测多个时域的视觉/自车状态 latent；当前证据走残差主路径，未来经门控注入 DiT。规划梯度更新当前路径上的共享 encoder，但预测器及注入的未来通过 stop-gradient 隔离。TAB 将候选轨迹投影到图像，给沿途 tokens 添加软注意力偏置。[方法](https://arxiv.org/html/2609.26299v2)

NAVSIM v1 同一 ViT-B 主干、DiT、导航及自车状态条件下：

| 设定 | PDMS |
| --- | --- |
| 当前观测 Base | 88.9 |
| 仅辅助未来预测 | 89.0 |
| 完整未来注入，无 TAB | 89.6 |
| 未来注入 + TAB | 89.9 |

匹配注入条件、关闭 TAB 时，detach 为 **89.6**，让规划梯度经过注入路径为 **89.2**。另一消融中打乱未来时域次序仍为 **89.4**，不能据此声称模型已学到严格时序因果。v2 非反应式 one-stage EPDMS 为 **90.0**。[表 4/5、补充表 2/8](https://arxiv.org/html/2609.26299v2)

## 工程判断、局限与建议验证

门控是跨样本共享的时域权重，不是逐场景不确定性估计。未来可能提供有用上下文，但当前证据仍重要；没有交互闭环或实车证明。作者报告单 H20 **58.2 ms/帧**，未来模块比 Base 约多 **26 ms**，不等于目标车端验收；本站未复现。

建议用同一主干做“aux-only、detach 注入、联合梯度注入”三组，并对未来特征置零、跨样本交换、打乱时域。按遮挡和切入场景检查碰撞、进度、置信度及完整时延，确认模型是在利用场景未来，而非只从额外参数或更强 encoder 获益。
