## 为什么选

失败学习首先要回答“错在哪里、改多少才够”。本文将诊断绑定到模拟器可验证事件，再从训练轨迹库寻找在当前场景可行、且尽量接近失败预测的修正，避免把任何错误都改成整条专家轨迹。诊断只在训练时使用，也提供了不增加在线反思步骤的路径。

## 方法与关键结果

从 Qwen3.5-4B 自采样失败中提取碰撞时刻、对象/图像位置或驶出边界；不可可靠视觉定位的碰撞样本被丢弃。检索候选必须重新在当前场景通过 NC/DAC/TTC；Correction SFT 后接 Safety-Layered GRPO，推理直接输出轨迹。[方法](https://arxiv.org/html/2609.35078v1)

相同基线与失败集的 NAVSIM v1 消融：

| 阶段/对照 | PDMS |
| --- | --- |
| Base SFT | 87.7 |
| 人类 GT 修正 + 诊断 | 88.2 |
| 最小修正，无诊断 | 88.3 |
| 最小修正 + 诊断 | 88.6 |
| 再用 PDMS reward 做 RL | 91.1 |
| 再用分层 reward 做 RL | 91.7 |

最后两行从同一个修正 SFT checkpoint 出发，NC **98.2→98.7**、TTC **94.9→95.9**。但相对“人类 GT 修正 + 相同分层 RL”，完整方法 EP **89.0→87.2**：它仍有安全—进度取舍。[表 3–5](https://arxiv.org/html/2609.35078v1)

## 工程判断、局限与建议验证

89.4 EPDMS 是同 checkpoint 在**原 NAVTEST、修正后的 v2 扩展指标、单阶段**下计算，不是 NavHard 两阶段成绩。reward 的硬安全优先只保证奖励排序，不保证模型输出永远安全；模拟器边界、筛选掉的难定位碰撞及轨迹库覆盖也会影响结果。没有反应式闭环或车端时延验收，本站未复现。

建议在固定失败集、训练预算和起点 checkpoint 下比较三种修正监督，再按碰撞对象可见/不可见、进度和舒适性分层评估。对检索不到安全候选的场景保留明确统计，避免最难失败被过滤后让结果显得更好；用独立交互闭环检验奖励排序是否能迁移。
