## 为什么选

**未来生成的收益，是否可以通过表征监督获得？** 本文给出一个直接可测试的替代：保留动作学习，只让少量隐状态对齐未来特征。它的价值在于把昂贵的生成目标拆成更小的假设，便于判断未来信息是否值得加入训练，而不是先引入整套视频生成路径。

## 方法与关键结果

冻结 Cosmos 世界编码器提供未来帧目标，以 MLP 和 MSE 对齐 world-query 隐状态；默认 1 秒、4 秒各 4 个 query。推理去掉世界编码器和 projector，保留 query 供 Action Expert 读取。[方法](https://arxiv.org/html/2609.17728v1)

作者在 NAVSIM v1 navtest、单前视协议报告：SFT 对照 **87.92 → 89.13 PDMS**；后续 RFT 后 **88.85 → 90.03**。主表普通结果约 **90.0**，**94.2 是 best-of-6**，不能与单次输出直接混排。NAVSIMv2 的 SFT 结果为 **86.2 EPDMS**。[表 I–III](https://arxiv.org/html/2609.17728v1)

单 H200、batch=1 的轨迹预测均值 **152 → 153 ms**；四卡 SFT 的训练时间增加 **3.8%**，包含在线未来特征提取。低开销是相对该基线而言，不代表车端全链路只需 1 ms。[实现与表 IV](https://arxiv.org/html/2609.17728v1)

数值均为作者报告，本站未复现；NAVSIM 不等于真实交通长期交互闭环，也不据 best-of-N 宣称全面 SOTA。

## 工程判断、局限与建议验证

**编辑判断：**适合先作为训练期小改动验证，但对齐目标仍由实际发生的未来构成，不能自动学习其他动作的反事实后果。原文 vanilla 对照连 world queries 一起移除，因此消融收益尚不能完全分离“多了 query 容量”与“未来对齐损失”两项因素。

建议固定 query 数量、主干、训练曝光量与动作接口，比较“无对齐 / 当前帧对齐 / 未来帧对齐 / 打乱未来目标”，同时看闭环安全、长尾、梯度冲突和推理成本。先证明最终动作使用了这份表征，再考虑增加时间跨度或更强教师。
