## 为什么选

空间对齐并不能自动消除车辆几何、动态响应和驾驶习惯的差异。本文冻结视觉语言主干，只适配动作生成，并在相同参数量与训练预算下比较“生成完再改”和“每一步生成时改”。这比单纯比较小车与卡车总误差，更能指导适配模块放在哪里。

## 方法与关键结果

先用 **229 个真实施工/事故相关场景**微调 Alpamayo 1.5 的动作生成栈，再冻结模型、训练 FVS 对每个 flow step 的动作空间速度加残差。这里的 flow velocity 不是卡车物理车速。[方法](https://arxiv.org/html/2609.38570v1)

在 **26 个场景互不重叠的留出事件**上，以单候选、6.4 秒开环协议比较：

| 模型 | ADE / FDE（m） |
| --- | --- |
| 基础模型 | 2.6358 / 7.1830 |
| Targeted Truck-SFT | 1.1650 / 3.1590 |
| 最终动作 Transformer 残差 | 1.1276 / 3.0002 |
| FVS Transformer | 1.0035 / 2.6383 |

后两者同起点、同数据、同参数量/更新预算。表内方差来自**推理噪声 seeds**，不是多次独立训练；best-of-16 另属 oracle 指标，未混入此表。[表 I、协议](https://arxiv.org/html/2609.38570v1)

## 工程判断、局限与建议验证

结果只说明更贴近日志专家，不能证明车体扫掠空间、铰接约束或闭环碰撞通过验收。约 65 倍通用数据对照针对这两类长尾，并不证明少量定向数据普遍替代大数据。仍使用基础模型的固定动作解码；新增残差很小，也不能直接推断整车实时性。全部为作者报告，本站未复现。

建议保留目标场景与普通行驶两个独立测试集，固定预算比较动作栈微调、末端残差和 FVS；再加入真实车长/轴距/挂车的扫掠检查及闭环跟踪，确认没有为降低开环 ADE 而牺牲其他车型或常规工况。
